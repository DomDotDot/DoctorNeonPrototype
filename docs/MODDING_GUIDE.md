# Руководство по созданию модов для Doctor Neon

Добро пожаловать в руководство по моддингу для визуальной новеллы **Doctor Neon** (Ren'Py 8, Python 3).

Данная система позволяет сообществу создавать пользовательские модификации, заменять ассеты, добавлять озвучку, настройки и новые сценарии без вмешательства в исходные архивы базовой игры.

---

## 1. Архитектура и размещение модов

Все пользовательские модификации устанавливаются в отдельную директорию `mods/` в корневой папке игры (рядом с исполняемым файлом `.exe` и папкой `game/`):

```text
DoctorNeon/
├── game/
├── mods/                                <-- Папка всех модификаций
│   ├── mod_example_cyberpunk/           <-- Папка конкретного мода
│   │   ├── mod.json                     <-- Обязательный манифест мода
│   │   ├── icon.png                     <-- Квадратная 1:1 превью-иконка
│   │   ├── settings.json                <-- Файл настроек (опционально)
│   │   └── audio/                       <-- Ресурсы мода
│   └── mod_toki_pona/
│       ├── mod.json
│       ├── icon.png
│       └── tl/toki_pona/
```

> **ВАЖНО**: Не помещайте сторонние скрипты напрямую в папку `game/`! Это приводит к загрязнению файловой системы остаточными `.rpyc` файлами и может вызвать краш игры при удалении мода.

---

## 2. Манифест модификации (`mod.json`)

Каждый мод обязан содержать в своем корне файл `mod.json` в кодировке UTF-8.

### Пример `mod.json`:
```json
{
  "id": "my_awesome_mod",
  "name": "Название вашего мода",
  "version": "1.0.0",
  "author": "Ваш никнейм / Команда",
  "type": "asset_replacement",
  "description": "Краткое описание того, что делает этот мод.",
  "target_version": "0.8.x",
  "priority": 10,
  "icon": "icon.png",
  "has_settings": true,
  "settings_file": "settings.json"
}
```

### Спецификация полей манифеста:

| Поле | Тип | Обязательно | Описание |
|---|:---:|:---:|---|
| `id` | string | **Да** | Уникальный идентификатор мода (латиница, цифры, `_`). Например: `cyber_hud_mod`. |
| `name` | string | **Да** | Отображаемое название мода в интерфейсе игры. |
| `version` | string | **Да** | Версия модификации (семантическое версионирование, например: `1.0.0`). |
| `author` | string | **Да** | Имя автора или название команды разработчиков. |
| `type` | string | **Да** | Тип модификации: `"translation"`, `"asset_replacement"`, `"script"`, `"general"`. |
| `description` | string | Нет | Описание модификации (1-3 предложения), отображается в карточке мода. |
| `icon` | string | Нет | Имя файла 1:1 иконки (по умолчанию `icon.png`). |
| `priority` | int | Нет | Исходный приоритет загрузки (по умолчанию `10`). Чем выше число, тем раньше монтируются ресурсы. |
| `target_version` | string | Нет | Совместимая версия игры (например: `"0.8.x"`). |
| `has_settings` | bool | Нет | Флаг наличия настроек (по умолчанию проверяется наличие `settings.json`). Если `false`, шестеренка не отображается. |
| `settings_file` | string | Нет | Имя файла настроек в папке мода (по умолчанию `settings.json`). |

## 3. Квадратная превью-иконка 1:1

Внутриигровой Менеджер Модов Doctor Neon отображает превью каждого мода в квадратном формате 1:1:
- **Формат**: PNG (с поддержкой альфа-канала).
- **Разрешение**: от 128x128 до 256x256 пикселей (соотношение сторон строго **1:1**).
- **Имя файла**: `icon.png` (или имя, указанное в поле `"icon"` манифеста).
- **Стиль**: рекомендуется неоновый киберпанк-стиль с контрастным рисунком или логотипом мода.
- Если иконка отсутствует, игра автоматически отобразит стильный неоновый плейсхолдер.

## 4. Индивидуальные настройки мода (`settings.json` и Шестеренка `⚙`)

Если вашему моду требуются пользовательские параметры (громкость, включение спецэффектов, кастомный текст, палитры), создайте в папке мода файл `settings.json`. В интерфейсе рядом с модом автоматически появится кнопка **Шестеренка `⚙`**.

### Поддерживаемые типы параметров:
1. `toggle` — переключатель (ВКЛ / ВЫКЛ, `boolean`).
2. `slider` — числовой ползунок (`min`, `max`, `step`, `default`).
3. `input` — текстовое поле ввода (`string`).
4. `choice` — выпадающий список/циклический выбор вариантов (`choices: [{"label": "...", "value": "..."}]`).

### Пример `settings.json`:
```json
{
  "title": "Настройки мода",
  "description": "Конфигурация параметров модификации.",
  "options": [
    {
      "id": "enable_bloom",
      "name": "Неоновое свечение (Bloom)",
      "type": "toggle",
      "default": true,
      "description": "Включает усиленное свечение интерфейса."
    },
    {
      "id": "custom_volume",
      "name": "Громкость эффектов (%)",
      "type": "slider",
      "min": 0,
      "max": 100,
      "step": 5,
      "default": 80,
      "description": "Громкость звуков мода."
    },
    {
      "id": "callsign",
      "name": "Позывной игрока",
      "type": "input",
      "default": "NEON-77",
      "description": "Текстовое имя, отображаемое на терминалах."
    },
    {
      "id": "hud_color",
      "name": "Цвет темы",
      "type": "choice",
      "default": "cyan",
      "description": "Цветовая схема оформления.",
      "choices": [
        {"label": "Cyan (Бирюзовый)", "value": "cyan"},
        {"label": "Magenta (Пурпурный)", "value": "magenta"}
      ]
    }
  ]
}
```

### Как читать настройки в коде мода (API):
В скриптах Ren'Py или Python используйте встроенную функцию движка:
```python
# Синтаксис: get_mod_setting(mod_id, option_id, default=None)
is_bloom = get_mod_setting("my_awesome_mod", "enable_bloom", True)
volume = get_mod_setting("my_awesome_mod", "custom_volume", 80)
callsign = get_mod_setting("my_awesome_mod", "callsign", "NEON-77")
```

## 5. Управление приоритетами игроком

- Исходный приоритет задается автором мода в поле `"priority"` манифеста.
- Игрок в Менеджере Модов может кликать по кнопкам **`▲` (повысить)** и **`▼` (понизить)** приоритет мода.
- Моды с более высоким приоритетом загружаются в `config.searchpath` раньше и имеют преимущество при подмене одинаковых ресурсов.
- При необходимости игрок может сбросить порядок к авторскому кнопкой *«Сбросить приоритеты к дефолтным»*.

## 6. Поиск и фильтрация

Менеджер Модов оснащен:
- Поисковой строкой `🔍` (поиск по названию, автору и описанию).
- Фильтрами категорий: *Все*, *Переводы*, *Ассеты*, *Сценарии*, *Активные*.
- Сортировкой: *По приоритету ↓*, *По имени A-Z*, *По автору*.

## 7. Подмена игровых ресурсов (`config.searchpath`)

Тип мода `"asset_replacement"` позволяет подменять оригинальную музыку, звуковые эффекты, спрайты и фоны без перезаписи файлов оригинальной игры:

1. Внутри папки мода создайте структуру папок, повторяющую пути из `game/`:
   - Замена звука клика: `mods/my_mod/audio/sfx/button-click.opus`
   - Замена музыки: `mods/my_mod/audio/music/BGM/NeonCity.opus`
   - Замена фона: `mods/my_mod/images/bg/chapter1/scene01.webp`
2. При активации мода в Менеджере Модов его папка подключается с наивысшим приоритетом в поисковый путь Ren'Py (`config.searchpath`).
3. Игра автоматически загрузит файл из мода вместо оригинального.
4. При отключении мода игра мгновенно вернется к оригинальным ассетам.

## 8. Модульные моды (`type: "modular"`) и система хуков

Модульные модификации — это наиболее мощный тип модов в Doctor Neon. Они работают как полноценные модули движка игры (`game/modules/`), позволяя создавать экраны, добавлять механику, скриптовать сцены и изменять интерфейс.

### Как работает система хуков модулей:
1. Исходные файлы мода хранятся в папке `mods/<название_мода>/`:
   ```text
   mods/mod_example_cyberpunk/
   ├── mod.json                     <-- "type": "modular"
   ├── settings.json                <-- параметры конфигурации
   ├── icon.png                     <-- 1:1 превью-иконка
   └── cyberpunk_module.rpy         <-- скрипт модуля (или в подпапке module/)
   ```
2. **Автоматический хук во время игры**:
   - При включении мода система загрузчика "хукает" модуль в игровую директорию `game/modules/mods/<название_мода>/`, перенося скрипты и структуру папок.
   - Движок Ren'Py исполняет скрипты мода наравне со встроенными модулями игры.
3. **Безопасный анхук при отключении**:
   - При отключении мода в Менеджере (или отключении коммьюнити-контента) загрузчик полностью удаляет папку `game/modules/mods/<название_мода>/` и все сгенерированные файлы байткода `.rpyc`. Исходная директория игры остается абсолютно чистой.

### Mod Overlay API (Встраивание экранов):
Модули могут выводить свои экраны в Главном Меню и внутриигровом HUD:
```renpy
init 50 python:
    # Регистрация оверлея в Главном Меню
    register_mod_overlay(
        screen_name="my_custom_overlay",
        mod_id="my_modular_mod",
        category="main_menu",  # "main_menu", "ingame" или "all"
        order=10
    )
```

Защита экрана от отображения при выключенном моде:
```renpy
screen my_custom_overlay():
    zorder 50
    if getattr(persistent, "community_content_enabled", False) and is_mod_enabled("my_modular_mod"):
        # Код вашего экрана...
        text "Модуль активен!"
```

### Mod Hook API (События):
Модули могут подписываться на события и генерировать собственные:
```python
# Регистрация обработчика события
def on_player_action(*args, **kwargs):
    print("Событие получено:", args, kwargs)

register_mod_hook("on_cyber_pulse", on_player_action)

# Вызов события (из любой части кода мода или игры)
trigger_mod_hooks("on_cyber_pulse", callsign="NEON-77", power=100)
```

### Чтение настроек в реальном времени:
```python
callsign = get_mod_setting("my_modular_mod", "operator_callsign", "DEFAULT")
palette = get_mod_setting("my_modular_mod", "hud_color_palette", "cyan")
is_bass = get_mod_setting("my_modular_mod", "enable_bass_boost", True)
volume = get_mod_setting("my_modular_mod", "sfx_volume_multiplier", 80)
```
Когда игрок меняет значения в меню настроек (`⚙`), переменные в вашем экране обновляются на лету!
