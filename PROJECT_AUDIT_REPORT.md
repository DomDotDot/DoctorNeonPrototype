## Раздел 1. Исполнительное резюме и ключевые метрики

Настоящий технический аудит представляет собой всестороннее исследование исходного кода, системных модулей, инструментов автоматизации, графических, аудио и шрифтовых ресурсов проекта визуальной новеллы **DoctorNeonPrototype**. Проект демонстрирует высокий нарративный объем и развитую структуру игровых механик (инвентарь, глоссарий персонажей, система достижений, галерея CG, автоматическое затемнение говорящих, фоновая проверка обновлений и загрузка DLC).

Однако по результатам аудита выявлен комплекс критических архитектурных и ресурсных узких мест:
1. **Нарушение модели сохранения и отката (Rollback Safety)**: Динамические переменные инвентаря и глоссария инициализируются в контексте `init python:`, что приводит к их потере при сохранении/загрузке или откате. Для маскировки этой проблемы в Главе 5 разработчики применили искусственное отключение отката (`$ _rollback = False`), блокирующее базовую функцию визуальной новеллы.
2. **Сбои логики запуска и безопасность**: В процедуре запуска обнаружена логическая ошибка проверки метки DLC (`launch.rpy:79`), из-за которой встроенный установщик DLC никогда не запускается при прямом старте новеллы. В релизные сборки утекают сторонние отладочные демоны (`renpy_warp`), сканирующие TCP-порты пользовательских систем, модуль распаковщика DLC уязвим к атакам Zip Slip (CWE-22), а в главном меню для всех игроков безусловно включено меню разработчика и кнопка "Открыть весь контент" (`or True`).
3. **Колоссальный потенциал оптимизации дискового пространства**: При общем весе репозитория **5 182.23 МБ** (5.18 ГБ) рабочая директория игры `game/` занимает **620.79 МБ**. Из них **364.37 МБ (58.7% веса папки `game/`)** составляют балластные и неоптимизированные данные, которые могут быть устранены немедленно без малейшей потери качества звука или изображения.
4. **Массовый разрыв связей скриптов и ассетов**: Зафиксировано 274 обращения к 164 отсутствующим аудиофайлам в Главах 4.5–9, ряд неверных путей к текстурам интерфейса, критический баг регистра файловой системы Linux/Android (`absolutesIlence.png`), ненайденный ассет предмета инвентаря `images/items/mop.png`, а также отсутствие фонов и CG в кульминационном финале Главы 5.

### 2.1. Анализ `errors.txt` (Синтаксическая ошибка компиляции AST)
- **Точная запись в журнале**:
  ```text
  File "game/modules/achievements/achievements-setup.rpy", line 152: invalid syntax
      icon="images/achievements/neondetective.png",,
                                                       ^
  Ren'Py Version: Ren'Py 8.5.3.26051504
  Wed Sep  2 21:08:27 2026
  ```
- **Корреляция с кодом**: Файл `game/modules/achievements/achievements-setup.rpy`. В результате последующих правок код сместился на строку **349**.
- **Техническая первопричина**: Опечатка разработчика — установка двойной запятой `,,` в списке аргументов инициализации экземпляра `Achievement(...)`. Парсер Python AST в Ren'Py 8.5.3 не допускает пустых элементов между позиционными или именованными аргументами кортежа и аварийно завершает генерацию AST-дерева еще до запуска интерфейса и вывода сплешскрина.
- **Причина проникновения в репозиторий**: В проекте полностью отсутствовала автоматическая проверка синтаксиса компилятором Ren'Py в git hook и CI/CD пайплайне (`renpy lint`). Существующий скрипт статистики `tools/script_stats_linter.py` использует простые регулярные выражения для подсчета диалогов и не валидирует Python-блоки.
- **Текущий статус**: В текущей версии файла синтаксическая ошибка устранена, однако в модуле достижений сохраняются логические проблемы с сохранением состояния (см. дефект M5).

### 2.2. Анализ `traceback.txt` (Критический краш во время исполнения)
- **Точная запись в журнале**:
  ```text
  While running game code:
    File "game/script.rpy", line 62, in script call
      call chapter_5_rpy from _call_chapter_5_rpy
    File "game/game-scripts/chapters/chapter5/chapter-5.rpy", line 23, in script call
      call chapter5_cargo_dead_end from _call_chapter5_cargo_dead_end
    File "game/game-scripts/chapters/chapter5/7-daughter-truth.rpy", line 24, in script
      scene ch05_cg55_v01 with dissolve
    File "game/game-scripts/chapters/chapter5/7-daughter-truth.rpy", line 24, in <module>
      scene ch05_cg55_v01 with dissolve
                               ^^^^^^^ 
  NameError: name 'dissolv' is not defined. Did you mean: 'dissolve'?
  Fri Sep  4 01:09:17 2026
  ```
- **Корреляция с кодом**: `game/game-scripts/chapters/chapter5/7-daughter-truth.rpy`, строка **24**.
- **Техническая первопричина**: Опечатка в имени стандартного эффекта перехода Ren'Py (`with dissolv` вместо `with dissolve`). В синтаксисе Ren'Py оператор `with <expression>` вычисляет переданное имя как переменную в контексте хранилища Python. Поскольку переменная с именем `dissolv` не была определена, движок сгенерировал неперехваченное исключение `NameError`, прервавшее прохождение кульминационной сцены Главы 5.
- **Текущий статус**: Опечатка была исправлена локально в рабочем дереве, однако модификация файла `7-daughter-truth.rpy` осталась незафиксированной (`git status` фиксирует unstaged changes). Требуется обязательная фиксация коммитом.

### 2.3. Анализ `log.txt` (Диагностика процесса инициализации)
- **Ключевые аномалии журнала**:
  1. **Строка 43**:
     ```text
     INFO:renpy_warp_service:service thread started. periodically scanning ports for warp server
     ```
     Свидетельствует о неконтролируемом запуске фонового демона отладки VS Code (`renpy_warp`). Демон запускается через колбэк `renpy.config.display_start_callbacks` и производит постоянное циклическое сканирование диапазона TCP-портов `18600..18610` на локальном хосте.
  2. **Строка 46**:
     ```text
     UpdateCheck: Сравниваю сервер [[0, 8, 0]] и локал [[0, 8, 2]]
     ```
     Подтверждает запуск фонового сетевого потока проверки релизов на GitHub (`update_checker.rpy`) без верификации SSL-сертификатов (дефект H1).
  3. **Строки 41–64**:
     Циклический пересчет размеров экранного буфера (`virtual=(1920, 1080) physical=(2560, 1369)` повторен **12 раз подряд** в течение доли секунды), вызванный агрессивными перерисовками экранных дисплейблов на этапе загрузки главного меню.

### 3.2. Глубокий анализ ключевых подсистем движка

#### 1. Модель управления состоянием и поддержка Rollback
Архитектурный фундамент Ren'Py строго разделяет время инициализации сценария и время выполнения игры:
- Любые переменные, созданные в блоках `init:`, `init python:` или на уровне модулей Python, принадлежат неизменяемой структуре данных игры. Ren'Py рассматривает их как константы и не включает в снимки сохранений (`saves`).
- Механизм отката (`rollback`) отслеживает изменения **только тех переменных, которые были объявлены через ключевое слово `default`** или изменены в процессе исполнения сценария оператором `$ var = val`.

В текущей кодовой базе инвентарь (`inventory-class.rpy`) и досье персонажей (`bio_system-class.rpy`) нарушают эту парадигму:
```python
# ДО РЕФАКТОРИНГА (ОШИБКА: init python)
init -1 python:
    inventory_list = []
    selected_item = None
    inventory_allowed = False
```
В результате при любом откате колесом мыши назад или при загрузке сохранения инвентарь содержит данные из текущей памяти процесса, приводя к рассинхронизации предметов и квестов. Попытка скрыть этот дефект через `$ _rollback = False` в `chapter-5.rpy` является антипаттерном.

**Корректная архитектурная реализация**:
```renpy
# ПОСЛЕ РЕФАКТОРИНГА (КОРРЕКТНО)
default inventory_list = []
default selected_item = None
default inventory_allowed = False

init -1 python:
    class Item(renpy.store.object):
        def __init__(self, item_id, name, icon, description=""):
            self.id = item_id
            self.name = name
            self.icon = icon
            self.description = description
```

#### 2. Графический конвейер и производительность дисплейблов
Дисплейбл `LavaLampName` (`name_effects.rpy`) демонстрирует критическую проблему производительности. Вместо использования аппаратного ускорения, метод `render()` 25 раз в секунду инициирует создание нескольких экземпляров класса `renpy.display.text.Text`, расчет синусоид на CPU и перерисовку через `renpy.redraw(self, 0.04)`. Это приводит к непрерывной аллокации памяти в куче Python и частым паузам сборщика мусора (GC).

В Ren'Py 8.x анимированные градиенты текста реализуются через GPU-шейдеры:
```renpy
init python:
    renpy.register_shader("custom.gradient_shift",
        variables="""
            uniform float u_time;
            attribute vec2 a_tex_coord;
            varying vec2 v_tex_coord;
        """,
        vertex_300="""
            v_tex_coord = a_tex_coord;
        """,
        fragment_300="""
            float shift = sin(u_time * 2.0 + v_tex_coord.x * 6.28) * 0.5 + 0.5;
            gl_FragColor = mix(vec4(0.18, 0.63, 0.26, 1.0), vec4(0.54, 0.17, 0.89, 1.0), shift);
        """
    )
```

Аналогично, дисплейбл `Dimmer` в `auto-highlight.rpy`, возвращающий задержку `0.01` (100 кадров/сек) для пошагового пересчета `Matrix(...)`, должен быть заменен стандартным переходом ATL:
```renpy
transform speaker_highlight(is_active):
    easein 0.2 matrixcolor (BrightnessMatrix(0.0) if is_active else BrightnessMatrix(-0.25))
```

Единственный шрифт проекта `game/fonts/WDXLLubrifontTC-Regular.ttf` имеет аномальный размер **9.86 МБ** (10 336 832 байт).

*Причина*: Маркировка "TC" в названии шрифта обозначает Traditional Chinese (традиционный китайский). Шрифт содержит более 20 000 сложных восточноазиатских иероглифов, которые **никогда не используются** в DoctorNeonPrototype (новелла выпускается исключительно на русском и английском языках).

*Решение*: Выполнение процедуры сабсеттинга через утилиту `pyftsubset` (библиотека `fonttools`) с ограничением диапазонами:
- Базовая латиница и дополнения (U+0020-U+00FF, U+0100-U+024F)
- Кириллица и дополнительные кириллические знаки (U+0400-U+04FF, U+0500-U+052F)
- Типографическая пунктуация и знаки валют (U+2000-U+206F, U+20A0-U+20CF)

Размер оптимизированного шрифта составит **~220–300 КБ**, что обеспечивает моментальную экономию **~9.60 МБ (97.5%)**.
